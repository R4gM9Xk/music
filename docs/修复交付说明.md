## 二、逐项实现细节

### ① 坏文件自动跳过（01 #13b）

`app/src/main/java/com/local/music/player/MediaControllerEngine.kt`

- **可跳过白名单**（9 个错误码）：IO 丢失/不可读/越界、容器解析损坏/不支持、解码失败/格式不支持。
- **刻意不跳** `DECODING_FORMAT_EXCEEDS_CAPABILITIES`（设备能力不足，低端机会把整库跳空）、`BEHIND_LIVE_WINDOW`、`TIMEOUT`、`AUDIO_TRACK_INIT_FAILED`——跳了下一首同样失败，只会变成疯狂跳歌。
- **上限 5 次**：判定、自增、跳转在同一次回调内完成，防 binder 异步重入绕过上限。
- **队尾守卫**：`hasNextMediaItem()` 为 false 不跳，同时截断 `REPEAT_MODE_ALL` 下「队尾坏文件→跳回队首→再跳」死循环。
- **`autoSkipInFlight` 旗标**：跳过自身产生的 SEEK transition 与用户手动切歌无法区分，无条件清零会让上限永远达不到 → 反而复现无限切歌事故。
- **API 更正**：任务书写的 `skipToNextMediaItem()` 在公开 API 不存在（ExoPlayer 内部叫法），实际用 `seekToNextMediaItem()`。
- **配套修复 `onError` 语义**：新增 `recovered` 参数，跳过成功时不再把 `playing` 打成 false（否则每次遇坏文件界面闪一下「已暂停」）。

### ② 格式宣称修正（01 #14a）

`MediaLibrary.kt` + `Artwork.kt` + `ActionsSheet.kt`

- 保留 `mimeToCodec`（回答「这是什么格式」，展示用）与新增 `playableMime` 白名单（回答「本机能否播」，能力用）**分离**——否则修 APE 只能把它从映射表删掉，是把「不诚实」换成「信息缺失」。
- `DemoSong.playable: Boolean = true`（默认乐观：旧缓存/演示曲目不该被误标为不支持）。
- 无 MIME 时按扩展名兜底判 `APE/WMA/WV/DSF/DFF/TAK/TTA/MPC`。
- 歌曲信息面板显示「APE（当前设备不支持播放）」。

### ③ 专辑模型（02 缺口②）

`MediaLibrary.kt` + `AppState.kt` + `Artwork.kt`

- **扫描层**：`ALBUM_ARTIST` / `DISC_NUMBER` / `YEAR` 三列填入 DemoSong（`<unknown>` 归一空串）；`getColumnIndex`（非 OrThrow）守卫个别 OEM 漏列。
- **增量复用分支**：用**本次 cursor** 覆盖这三列——不覆盖会导致「升级后只要缓存命中这三列永远为空」，是最难排查的一类 bug。
- **缓存贯通**：`library_cache.json` 增三键，读侧 `opt*` 带默认值，**CACHE_VERSION 不升**（升版会让所有老用户强制全量重扫，万首库分钟级）。
- **分组键**：`(专辑名, 专辑艺术家)` 二元组，`albumArtist` 缺失回退 `artist`（**没标签的库升级后观感零变化**）。
- **展示与定位分离**：`LibraryGroup.key` = 专辑名（展示），`LibraryGroup.id` = `专辑名\u0000专辑艺术家`（定位）。`DetailTarget` 按 `id` 找，两张同名专辑不再进同一页。
- **`albumId` 单一编码点**：`albumGroupsFrom` 与 `albumIdOf` 共用，避免「改了分组忘了反查」。
- **曲序排序**：`(discNo, trackNo, title)` 升序，未知（0）排**末尾**而非当第 0 首排最前；同值用中文 Collator 保证稳定。
- **`albumCountByArtist`** 改用专辑艺术家口径（合辑不再算到首曲艺术家头上）。
- **LazyColumn key** 用 `album.id`——用 `key` 时同名专辑 key 重复会**直接崩溃**。

### ④ 音频链（01 #4/#6）

`ReplayGainParser.kt`（新建）+ `MusicPlaybackService.kt` + `AudioFxState.kt`（新建）

- **A 路线：真 ReplayGain 解析**（非降级固定增益）。手写纯 JVM 解析器：ID3v2.2/2.3/2.4 `TXXX` 帧 + FLAC Vorbis comment（大小写不敏感），**排除 ALBUM_GAIN**（单曲乱序用专辑增益会响度错）。
- 读不到标签时**不做任何补偿**——固定增益解决不了曲目间响度差，还会把本已录得响的歌推爆成削波。
- **B：3 个开关**（响度归一 / 低音增强 / 虚拟环绕），后两者各 3 档强度。
- **全部默认关**：升级后用户听到的声音与升级前逐比特一致（单测 `AudioFxStateTest.默认设置三项全关` 钉死）。
- 会话变更重建 + 全路径 release + `runCatching` 兜住（蓝牙 A2DP/USB DAC 上 audiofx 常不生效）。
- **未覆盖**：OGG/Opus、M4A iTunNORM、WAV rgan、APE（注释已写明）。
- **C 未做**：EQ 自定义预设保存（不在本轮 P0，属锦上添花）。

### ⑦ 分享 / 设为铃声（03 #16）

`app/src/main/java/com/local/music/share/ShareActions.kt`（新建）+ `SystemActions.kt`

- **分享歌曲**：走 MediaStore `content://` **直发**，不走 FileProvider——`file_paths.xml` 只暴露 `files/update`，为分享加 `external-path` 等于把用户全盘存储开给任意 App。
- 无 `mediaUri` 的曲目退化为纯文本分享（歌名+艺术家），不报错（点了没反应是最差体验）。
- **设为铃声**：优先系统铃声选择器；`setActualDefaultRingtoneUri` 需 `Settings.System.canWrite()`，无权限时引导授权页。国内 ROM 行为不一致，全程 `runCatching` + 失败给文案。
- **分享歌单**：导出 M3U 后经 FileProvider 分享（只暴露 `share/` 子目录）。

### ⑧ 桌面小部件 + 桌面歌词（03 缺口1）

**小部件** `app/src/main/java/com/local/music/widget/`（新建 5 文件 + 2 布局 + 6 drawable + 2 appwidget-provider）
- 走 **RemoteViews** 而非 Glance：本机离线缓存里 `glance` 产物被 Gradle GC 回收，且其传递依赖（compose 1.7.8 / kotlin-stdlib-common 2.0.21 / work-runtime 2.7.1）与工程锁定的版本（compose 1.10.0 / kotlin 2.2.20）对不上——**即使缓存没被回收也编不过**。
- 双尺寸：4×1 播放条、4×2 封面版。
- 控制动作经 `WidgetActionReceiver`（BroadcastReceiver，`exported=false`）转发，**不长期持有 MediaController**（Receiver 生命周期极短）。
- `MusicWidgetRefresher` 幂等 + 节流 + 内部 try/catch，挂在 `onMediaItemTransition` / `onIsPlayingChanged`。
- PendingIntent 全部 `FLAG_IMMUTABLE`。
- `libs.versions.toml` 里三个 glance 坐标**有意保留**（记录原本设计意图，联网补缓存后可按注释切回）。

**桌面歌词** `app/src/main/java/com/local/music/lyrics/`（新建 4 文件）
- 服务驱动（`MusicPlaybackService` 构造注入 `positionMsProvider` / `currentTrackPathProvider`）——桌面歌词的使用场景就是**离开 App 之后**，Activity 驱动等于没做。
- `TYPE_APPLICATION_OVERLAY` + `FLAG_NOT_FOCUSABLE`（不设会抢焦点顶掉输入法）+ 可拖动（8px slop 区分手抖）。
- 250ms 轮询 → 二分找当前行 → 文本变了才 setText。
- 无歌词显示「♪ 暂无歌词」显式空态而非隐藏窗（否则用户分不清「开关坏了」还是「这歌没词」）。
- 权限：manifest `SYSTEM_ALERT_WINDOW`；未授权时 `canDrawOverlays()` 为 false → 跳 `ACTION_MANAGE_OVERLAY_PERMISSION`（带 package uri，三级回退）。
- 所有 WindowManager 操作 `runCatching`；`onDestroy` 首行 `release()` 摘窗（否则进程死后留「孤儿窗」）。
- 开关持久化用**独立 DataStore**而非 AppStateSnapshot——后者 v1→v10 迁移链已被 137 条单测钉死，为布尔键升版风险远超收益。

### ⑨ 备份 re-match（02 缺口③）

`core/ui/src/main/java/com/local/music/core/ui/state/SongRematch.kt`（新建）+ `SettingsStore.kt` v10

- **4 级匹配**：①文件名+时长(±2s) ②文件名 ③标题+艺术家+专辑 ④标题+艺术家。
- **指纹表 `trackRefs`（快照 v10）**：每首存 `[title, artist, album, durationSec]` 4 元数组（数组形态而非对象，万首库省约 2.4MB 纯键名）。旧备份无此字段 → 空表零迁移，退化为「只按文件名匹配」，仍远好于旧实现。
- **不再静默**：恢复后经顶部横幅告知「已恢复 X 首，Y 首未找到（文件路径已变化）」。
- 单测 `SongRematchTest` 24 条覆盖 4 级优先级与全失败场景。

### ⑩ 工程项（04）

- **崩溃日志闭环**：`CrashHandler`（已有）→ 补上**设置页导出/清空入口**（此前日志躺在手机里导不出来，等于没做）。`feature:settings` 不能依赖 app 模块，故走「app 层持 SAF 回调 + 屏内只拿数量与动作」的解耦。
- **AppState clock 注入**：`class AppState(private val clock: () -> Long = System::currentTimeMillis)`，9 处 `System.currentTimeMillis()` → `clock()`。这是 04 #6 所说「投入产出比最高的一步」——睡眠定时/队列节流第一次可确定性测试。
- **新增单测**：`AppStateClockTest` 6 条（用假时钟推进验证递减、到期钳 0、播完档 null、重设基准）。
- **R8**：`isMinifyEnabled = true` + `isShrinkResources = true` + `proguard-rules.pro`（保留 Media3 反射路径、枚举 values/valueOf、AppWidgetProvider、崩溃栈行号）。
- **签名**：从 `local.properties` / 环境变量读 keystore，**读不到回退 debug 签名并打印警告**——硬编码正式 key 会让 CI 与新人 clone 后构建不了。
- **实测收益**：release APK **29.6 MB → 5.7 MB（−80.7%）**。

## 五、协作过程记录（供复盘）

本轮 10 个任务由 9 个并行 agent 分担，出现过一次**「按功能域切任务而非按编译单元切」的编排失误**：`app` 是单一编译单元，任何 agent 写到一半都会让所有人的 `:app:compileDebugKotlin` 变红，四个 agent 一度同时被阻塞。

期间的真实冲突与处理：
- 三个 agent 掉线（`library-dev` / `test-infra-dev` / `lyrics-dev` 中途失败），其任务由 Lead 接手完成。
- `SettingsStore.kt` 曾出现 `TEMP-DEBUG` 调试残留（把 `runCatching` 从一条分支挪走），导致 **debug 能编过、release 编不过**——已恢复为两条分支统一包 `runCatching`，并注释记录这段历史。
- `AppState.kt` 曾因多次编辑叠加出现 `albumGroupsFrom` 重复定义 + 孤立代码残片，已清理。
- `strings.xml` 与 `widget_strings.xml` 曾重复定义 `widget_desc_wide/square` 阻塞打包，已去重。

**教训**：后续批次应按「编译单元 + 单次合并」排，或给每人独立的 `:app` 子集编译目标。
